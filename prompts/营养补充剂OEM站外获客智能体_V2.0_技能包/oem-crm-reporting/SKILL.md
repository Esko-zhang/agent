# S15 台账、日报与渠道复盘

## 目标
让每次运行都能从上次中断的地方接着做，并保证台账准确。每天告诉团队今天该跟进谁；每周告诉团队哪个渠道有效、下周改什么。

## 输入
各技能的输出、台账的 5 个工作表、run_config、授权记录。

## 步骤
A. 台账
1. 每个技能结束后立即写入台账，不等整轮结束后再补录。使用 upsert（ID 相同就更新，不新增重复行）；合并时保留来源和旧 ID。
2. 写入前检查：关联的 ID 存在；时间带时区；来源 URL 可追溯；总分等于各项之和；状态在允许的取值范围内；没有回执的记录不能记为 SENT。
3. 禁联记录优先级最高，任何导入都不能覆盖它。
4. 保存 checkpoint：run_id、已处理的 ID、未完成的队列、已用的额度、错误、下一步。重启后从 checkpoint 接着做，不重复首次触达。
5. 台账写不进去时：输出完整的待保存内容，明确标注“未保存”，并停止自动发送。

B. 日报（每个工作日）
6. 按以下顺序输出：结论（5 行以内）→ 今日优先客户（最多 10 家）→ 各渠道计数（采集 / 核实 / A 和 B 级 / 草稿 / 已发邮件 / 人工待发 / 回复 / 有效回复 / SQL / 移交）→ 人工待办（人工发送清单、待审草稿、待回答的问题）→ 阻塞与缺口 → 明天的计划。

C. 周报（每周五）
7. 按 A 海关、B 电商、C 地图、D 社媒、E 新品牌、F 独立站分别统计：核实的公司数、首次触达的公司数、真人回复、有效回复（讨论产品、规格、价格、时间或转介；不包括拒绝和自动回复）、SQL、报价、样品。
8. 每个比率都要写出分子、分母和观察窗口。首次触达不满 10 天的公司单独列为“未成熟”，不计入回复率。
9. 回答四个问题：
   - 哪个渠道带来了真实项目？
   - 哪一步最耗时？
   - 客户不推进的主要原因是什么？
   - 下周只改哪一个变量（例如某个渠道的配额、某个切入角度、某组关键词），用什么标准判断有没有效果？
10. 可以在授权范围内调整关键词和渠道配额（±10 个百分点）。扩大市场、提高发送量、增加预算，需要用户批准。

## 输出
台账变更记录、checkpoint、日报 / 周报（保存到 06_Outputs/，并推送到指定的消息入口）。
