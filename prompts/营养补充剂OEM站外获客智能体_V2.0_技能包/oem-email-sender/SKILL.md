# S11 邮件发送与邮箱健康

## 目标
作为唯一的自动发信出口，在有效授权和邮箱健康限额之内，把到期的邮件准确地发出一次，同时保护发信域名的信誉。

## 输入
DRAFT / APPROVED 的触达卡、有效的授权记录、run_config（邮箱、日上限、发送窗口、退信阈值）、台账（Touches / Suppression）、Gmail / Workspace 连接器、最新的收件检查结果。

## 步骤
1. 确认 mode=AUTO_EMAIL、global_pause=false，而且授权覆盖本次涉及的公司、联系人、内容版本、序列步骤和有效期。不满足就保持草稿，并列出原因。
2. 检查邮箱健康：每个发信邮箱当天已发的数量、预热是否完成、最近 7 天的退信率和投诉情况。退信率超过阈值、出现投诉或账号受限时，暂停该邮箱并报告。
3. 每封邮件发送前逐项检查：
   - 联系闸门仍为 PASS；
   - 不在禁联表；
   - 15 分钟内查过收件箱，对方没有回复；
   - 同一家公司今天没有其他触达；
   - 满足序列间隔（D0 / D4 / D10）；
   - 收件人当地时间是工作日 9:00–16:00；
   - 内容与批准的版本一致，没有占位符。
4. 在多个邮箱之间轮换，单个邮箱不超过当日上限；两封邮件之间随机间隔 2–6 分钟。
5. 发送前在 Touches 中写入 SENDING 和幂等键（lead_id + contact_id + step）。写入失败就不发送。
6. 连接器返回成功和 message_id 才记为 SENT。超时或结果不明时记为 UNKNOWN，先到“已发送”文件夹核对；确认没有发出之前不重发。
7. 发送后更新 next_action_at（下一步的日期，遇到收件人当地的周末就顺延）。
8. 退信：出现硬退信，立即把该地址设为 INVALID，停止这位联系人的序列。可以改用同一公司另一位已验证的联系人，但要重新检查闸门和授权。

## 输出
发送报告：SENT / UNKNOWN / FAILED / BLOCKED（附原因），各邮箱的用量和健康状况，暂停事件。

## 规则
不换新邮箱或新域名来绕过暂停；不发附件；不加追踪像素；不自动报价。
