# S02 客户画像与每日获客计划

## 目标
把“卖什么、卖给谁、去哪里找”变成今天可以直接执行的任务清单，并保证不重复搜索同样的内容。

## 输入
run_config（市场、产品、客群、渠道权重、额度）、产品卡、台账中已执行过的关键词 / 城市 / HS 编码 / 竞品工厂记录、上周各渠道的数据。

## 步骤
1. 确定本轮范围：1 个主市场 + 最多 1 个次市场；2 条产品线；2 类主攻客群。用户没有指定时，使用 run_config 的默认值，并标注为“假设”。
2. 按渠道权重，把今天的原始候选配额（默认 60 条）分给 A–E 五个渠道。如果上周某个渠道的核实率或有效回复率明显更高，可以在 ±10 个百分点内调整，并写明理由。
3. 从 03_Channels 的矩阵里挑出今天还没做过的组合，为每个渠道生成具体任务：
   - A 海关：今天反查哪 5–8 家竞品工厂；用哪 2–3 组产品关键词或 HS 编码。
   - B 电商：今天看哪 3–4 个“子类目 × 剂型”的 Best Sellers / New Releases；TikTok Shop 搜哪些词。
   - C 地图：今天跑哪 2–3 个城市、哪 2 类关键词。
   - D 社媒：今天搜哪些求购短语和话题标签；为哪些已核实的公司找决策人。
   - E 新品牌：USPTO 查询的日期区间和关键词；本月相关展会的名单。
4. 每条任务都写明：目标客群、要验证的事实、最多查看几页、停止条件（例如连续 2 页没有新的合格公司就换关键词）。
5. 维护关键词和城市的轮换表：做过的组合记下日期，30 天内不重复，除非上次效果好。
6. 检查预算：页面数、运行时长、付费调用（默认 0）。任一项达到上限就停止。

## 输出
今日任务清单（渠道｜任务｜关键词 / 城市 / 对象｜配额｜停止条件）、ICP 摘要、预算、需要用户确认的问题（最多 2 个）。任务交给各采集技能执行；用过的组合交给 S15 记录。

## 质量标准
每条任务都能直接执行；不擅自扩大市场、产品或发送范围。
