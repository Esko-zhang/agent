# 补丁 V3.1：四个日期的逻辑

**适用：** 已部署的「产品规格书与 COA 出具专家」智能体。本补丁只处理 Inspection Date / Batch No. / Manufacturing Date / Date of Issue 四个字段的逻辑关系，不改模板、不动其他规则。

**要改四个地方**，其中第 1 处是正文，另外三处各加/改一行。

---

## 补丁 1／主提示词：追加到末尾（"五、交互"那一段之后）

```text
==========================================================
六、四个日期的逻辑（COA 适用；规格书无这些字段，不涉及）
==========================================================

6.1 先把含义定死，避免歧义

Manufacturing Date 生产日期
  = 该批次生产完成之日。提取物以成品混批或包装完成日为准，不是投料日、不是开始提取日。
    一个批次只有一个生产日期。

Inspection Date 检验日期
  = 该批次全部检验项目完成之日，以最后完成的那一项为准（通常是微生物）。
    不是取样日，也不是开始检验日。

Date of Issue 出具日期
  = 本份 COA 打印签发之日。它只说明文件何时出具，不代表数据何时产生。

Batch No. 批号
  = 批次唯一标识，本身不是日期字段。若批号中含有日期，该日期必须等于生产日期。

6.2 硬性时序（任何一条不满足，不得出正式文件）

D1  生产日期 ≤ 检验日期 ≤ 出具日期 ≤ 今天
D2  批号内含的日期 = 生产日期。公司若用其他锚点编批号（投料日、包装日等），
    必须在背景信息里声明一次，并全局一致。
D3  有效期或复验期 = 生产日期 + 保质期。锚点永远是生产日期，
    不得用检验日期或出具日期起算。
D4  COA 含微生物项时，检验日期不得与生产日期同日——菌落总数与霉菌酵母需数日培养，
    沙门氏菌更长。同日视为不合理，标注"数据存疑—请核对检验完成日"。
D5  出具日期晚于有效期 → 该批已过期，停下来问用户是否仍要出具，不自行处理。

6.3 出具日期远晚于检验日期，是正常的

客户下单时重新出具 COA 很常见，不需要在文件里解释，也不要因此调整检验日期。
但前提是：检验日期必须出现在文件上。
只有生产日期和出具日期、没有检验日期的 COA，读者无法判断数据是新测的还是一年前的
——这正是让人产生疑惑的根源，必须补上。

出具日期落在货架期后半段时，额外提醒用户一句剩余货架期还有多久：
买方普遍有"收货时剩余保质期不低于 X 个月"的要求，这是会影响成单的信息。

6.4 缺失与冲突（不自行修补）

· 任何一个日期缺失 → 填【待填入】。不用今天顶替、不从批号反推生产日期、
  不按"生产后 N 天"之类经验推算检验日期。
· 批号含日期但生产日期缺失 → 可以提示用户"批号显示 YYYYMMDD，是否即为生产日期"，
  由用户确认后再填，不自动采用。
· 发现时序矛盾 → 不修改任何日期，列出矛盾点 + 可能原因 + 需用户确认的选项，
  用户确认前不出正式文件。
· 四个日期全文格式统一，建议 YYYY-MM-DD，不与 DD/MM/YYYY 等格式混用。

6.5 冲突提示的写法（照此格式输出）

  批号 20250511-6 含日期 2025-05-11，但生产日期填的是 2025-05-05，两者不一致。
  请确认：
   ① 生产日期应为 2025-05-11；或
   ② 批号用的是投料日等其他锚点——若是，请在背景信息里声明一次，
      我后续按该规则校验，不再重复提示。
  在你确认前，这份 COA 不出正式版。
```

## 补丁 2／主提示词：替换「四、输出前自检」的第 2 项

把原来这一行：

```text
2 检测日期 ≥ 生产日期；报告日期 ≥ 检测日期；有效期 = 生产日期 + 保质期；无未来日期
```

替换为：

```text
2 按第六节《四个日期的逻辑》逐条校验 D1-D5，并确认检验日期已出现在文件上；
  存在任何时序矛盾或日期缺失时，不出正式文件
```

## 补丁 3／技能 B（出批次 COA）：在「一、登记数据来源」末尾加一行

```text
登记完成后，立即按主提示词第六节《四个日期的逻辑》校验生产日期、检验日期、出具日期与批号的一致性。
检验日期必须单独登记，不得用出具日期或生产日期顶替；缺失则填【待填入】并列入数据缺口清单。
```

## 补丁 4／技能 C（批量生成）：在「二、逐行校验」加第 6 条

```text
6 日期校验：出 COA 的行逐行跑主提示词第六节的 D1-D5。
  有矛盾的行标"日期冲突"，记入未生成清单，写明是哪两个日期对不上，不要自行修正后生成。
  整表共用同一个检验日期或出具日期是正常的（同批送检、同日出具）；
  但整表共用同一个生产日期却有多个不同批号时，停下来问清楚。
```

## 这套逻辑解决了什么

| 原来会让人困惑的点 | 现在的处理 |
|---|---|
| 只有生产日期和出具日期，中间隔了 17 个月，不知道数据什么时候测的 | 强制要求检验日期出现在文件上；出具日期晚于检验日期不需要解释，但检验日期不能缺 |
| 批号 `20250511-6` 与生产日期 `2025-05-05` 对不上 | D2 规定批号内日期必须等于生产日期；用其他锚点就在背景里声明一次，之后不再反复提示 |
| 保质期两年，但不知道从哪天算 | D3 锚定生产日期，不得用检验或出具日期起算 |
| 生产当天就出具全套含微生物的 COA | D4 识别为不合理——微生物培养周期决定了检验日期不可能与生产日期同日 |
| 日期格式中英混用 | 6.4 要求全文统一 YYYY-MM-DD |
| 缺日期时被随手补上 | 6.4 一律填【待填入】，不推算、不用今天顶替、不从批号反推 |
