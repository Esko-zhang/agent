# Skill｜Backend Operations — 后台连接、写入、核验与回滚

> 授权分级（L0–L3 与禁区）、证据写入门槛、状态枚举以主提示词为准，本 Skill 只规定“怎么操作”。

## 一、连接与后台识别（P0）

1. 确认 Accio Work 浏览器已连接，且用户已在自己的浏览器中登录后台。不索要、不复述、不记录密码、验证码、Cookie 或 Token。
2. 核对当前域名、店铺/站点 ID、生产站或测试站。存在多个相似站点时保持只读，直到用户确认。
3. 识别后台类型：Shopify / WooCommerce / Magento / Shopyy / 自研。无法确认时记为 `CUSTOM_OR_UNKNOWN`。
4. 找到入口：产品列表、产品编辑、分类、标签/属性、附件/媒体、导出、导入、版本历史。
5. 在一个样例产品上**打开编辑页但不保存**，建立字段映射：
   - 主键（Product ID）与 SKU
   - 标题、简短描述、详细描述（区分富文本可视区与 HTML 源码）
   - 主分类、附加分类、标签
   - 规格属性 / 自定义字段 / 变体
   - 上架状态、可见范围
   - 图片、附件
   - 价格、MOQ、库存（只记录位置，不在授权外改动）
   - 保存按钮的含义：Save Draft / Save / Update / Publish 是否分开
6. 记录实际观察到的权限：READ / EDIT / EXPORT / IMPORT / CATEGORY_EDIT / MEDIA / PUBLISH / DELETE。按钮可见不等于有写入权限；写入权限要以首次试点保存成功为准。
7. 产品总数以导出结果或完整分页为准。列表有筛选、分页或懒加载时，不得用一页数据推算全站总量；草稿、归档产品要单独说明是否包含。

输出：`site_origin / admin_url / site_system / environment / permissions_observed / product_count_observed / field_map / save_behavior / export_supported / import_supported / version_history_supported`。值必须来自实际读取，不得预填。

## 二、备份（P1）

- 优先使用后台官方导出，导出范围覆盖本次授权的全部产品及分类关系。
- 没有导出功能时，逐个读取并保存为表格：Product ID、SKU、全部将修改字段的旧值、分类 ID、上架状态、编辑页 URL。
- 同时保存分类树：`category_id, parent_id, name, visible, product_count`。
- 命名：`baseline_YYYYMMDD_<batch_id>.xlsx`。告知用户文件位置。
- 区分 `BACKUP_EXISTS`（有旧数据）和 `ROLLBACK_TESTED`（已验证能恢复）。不能因为导出成功就声称可以一键回滚。
- 备份中不保存密码、Token、客户联系方式、订单数据。
- **没有完成备份，不进入任何写入。**

## 三、单条产品编辑流程（模式 A：浏览器编辑）

1. **定位**：用 Product ID 或唯一 SKU 打开编辑页。不按列表行号定位，分页和排序会改变行位置。
2. **核对身份**：ID、原标题、类型与台账一致才继续，否则退出重新定位。
3. **冻结旧值**：读取所有将修改字段及可能联动的字段，写入台账 `before`。读不到旧值的字段不改。
4. **过滤**：只保留授权范围内、证据达到写入门槛、且产品不在 HOLD 中的字段。
5. **写入**：在真实控件中填写。以控件实际显示的值确认输入结果，不能只看操作命令是否报错。
   - 富文本：防止编辑器吞掉表格、换行和特殊符号（µg、β、≥、±）。已有自定义 HTML 或图文组件时只改允许区域，不整页覆盖。
   - 分类：选择真实存在的分类 ID，注意区分主分类与附加分类，注意分类与标签是不同控件。
   - 规格属性与正文中的同一指标必须一致；冲突时停止该字段，记入待核实。
6. **检查未授权字段**：保存前确认价格、库存、MOQ、上架状态、可见范围、供应商等字段没有被联动改变。
7. **保存**：用户只授权草稿时只点保存草稿，禁止点发布。
8. **回读**：等待明确的成功提示，然后刷新或从列表重新打开该产品，逐字段比对目标值；分类比对 ID 或准确名称。
9. **登记**：写入台账状态，记录保存时间与回读时间。

## 四、批量写回（模式 B：官方导入 / 授权 API）

适用：后台支持导入，且同类修改超过 30 个产品。
1. 必须使用后台官方导入模板。中间台账的 CSV 表头不是任何后台的通用导入格式。
2. 以 Product ID / 唯一 SKU 做增量更新，禁止产生新产品。
3. 只填写计划内的列；其他列保持导出时的原值。先用 1–2 行样本测试后台对空白列的处理：空白是“保持不变”还是“清空”，确认之前不做全量导入。
4. 有导入预览或 dry-run 就先用。
5. 导入后再次导出，与变更计划逐字段对比，并核对产品总数前后一致。
6. 出现重复 SKU、字段被清空、分类错误、可见范围变化中的任何一项，立即停止，按授权回滚并报告。
7. 只在后台提供官方 API 且用户授权时使用 API。不调用后台未公开的私有接口，不从开发者工具抓取 Token。

## 五、批次节奏

- 试点 3–5 个产品，覆盖原料和 OEM 成品，全部回读一致后提交试点报告。
- 试点通过后每批 10–20 个（后台慢或不稳定时减少），每批生成 `batch_id`，结束后输出本批统计。
- 单个产品出现身份或合规问题，只把该产品移入 HOLD，不停止整批。
- 出现写错产品、字段被清空、重复创建、敏感信息暴露，立即停止整个批量。
- 中断后按 `batch_id + product_id + 当前字段值` 续跑：先重新读取目标产品，只补未完成字段，不重复提交已成功字段。

## 六、失败处理

| 代码 | 情况 | 处理 |
|---|---|---|
| `VALIDATION_ERROR` | 必填项或格式不合法 | 不保存，修正后重做 |
| `PERMISSION_DENIED` | 权限不足 | 停止该类写入，报告需要的权限 |
| `CONCURRENT_EDIT` | 他人刚修改过该产品 | 读取当前版本，不覆盖他人修改，报告冲突 |
| `PARTIAL_SAVE` | 部分字段生效 | 只补差异字段，或回滚到原值 |
| `NETWORK_TIMEOUT` | 超时 | 先回读确认是否已保存，再决定是否重试 |
| `WRONG_PRODUCT` | 写到了错误产品 | 立即暂停批次，按备份恢复并回读，报告事故 |
| `DUPLICATE_CREATED` | 导入产生了重复产品 | 暂停批次，记录重复项，申请清理授权 |
| `SENSITIVE_DATA_EXPOSED` | 价格、客户配方等被公开 | 立即停止，在报告中提示用户处置，不在报告中复述敏感内容 |

同一产品同一操作最多安全重试 1 次；连续 2 个产品失败则暂停批次。

## 七、回滚

- L1 误写：按备份旧值恢复，回读确认，记为 `ROLLED_BACK_VERIFIED`。
- L2 结构变更的回滚会影响整类产品，先说明影响并取得确认后再执行。
- L3 操作在回滚能力未验证前不得启动。
- 回滚同样写入变更日志。

## 八、买家端核验（有买家视角权限时）

- 用买家账号查看产品卡、详情页、分类筛选、询盘按钮。
- 不提交真实询盘、不触发邮件；用户授权测试时使用测试邮箱并标注 TEST。
- 没有买家权限时，报告写“买家端未核验”，不得声称已验证。
