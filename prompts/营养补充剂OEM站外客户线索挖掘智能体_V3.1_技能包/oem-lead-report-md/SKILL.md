# S10 Markdown 客户清单输出

## 目标
把 S09 放行的客户，按固定模板生成一份 Markdown 文件，交给用户直接使用；同时更新线索总库，保证下次运行不会重复。

## 输入
S09 的交付清单、待确认清单、更新清单、质检报告，run_config.output。

## 格式规则
1. 文件名：每日为 `客户线索_{日期}_{市场}.md`；每周汇总为 `客户线索周汇总_{年}W{周}.md`。保存到 run_config.output 指定的目录。
2. 表格单元格里不能有换行，不能有竖线“|”（改成“／”）；多个值用“；”分隔；空值写“—”。
3. 网址写完整的 https 链接；电话用国际格式；WhatsApp 写成 https://wa.me/号码。
4. 邮箱后面用括号标注等级，例如 jane@brand.com（A1）。
5. 公司名、人名、职位、地址保留原文，其余内容用中文。
6. 不写任何未经 S08 核验的联系方式；待确认清单里只写公司名、网站和缺少的内容。

## 模板（照此输出，【】替换为实际内容）

```markdown

- 背景调查：所有交付客户都已通过企业存续、经营活跃度、负面信息、联系人在职和联系方式来源的核验；每个字段的核实日期见详情卡
```

## 步骤
1. 按模板生成文件；客户数量超过 50 家时，详情卡照常全部列出，总表放在最前面。
2. 保存文件后重新读取一次，检查：表格列数一致；没有残留的【】占位符；每家详情卡都有“背景调查”表；总表和详情卡的数量一致。
3. 更新线索总库：交付的写入 delivered_in_file 和 last_verified_at；PENDING、REJECTED 的写入 background_status 和原因。
4. 每周汇总：合并本周每日文件中的客户，按等级重新排序；核实日期超过 7 天的字段，先交给 S08 重新核验再写入。
5. 在对话中输出运行摘要：交付数（A/B/C）、待确认数、排除数及主要原因、各渠道的背调通过率、遇到的访问限制、文件路径。

## 规则
没有写入工具时，直接在对话中输出完整的 Markdown 内容，并明确说明“未保存为文件”；不能说“已保存”。
