# Durlevel 外贸独立站 — 规划方案

> 本方案依据需求 Excel（`首页` / `产品列表页` / `联系我们` 三个 Sheet）整理而成。

## 一、需求还原

### 1. 首页 = 登录页（Sheet「首页」）
- 页面主体只有三个元素：**Logo**（大图区 B12:H26）、**登录账号**输入框、**登录密码**输入框。
- Excel 批注明确了账号体系：
  1. **管理员账号**：可登录网站后台，设置网站信息与产品信息，并可创建 / 修改用户账号和密码；
  2. **用户账号**：**不开放自助注册**，只能由管理员在后台创建；用户登录后只能浏览网站前台。
- 结论：**整站内容在登录之后才可见**（闭环式询盘站），首页即登录闸门。

### 2. 产品列表页（Sheet「产品列表页」）
- 顶部：**品牌 Logo** + **搜索框**。
- 分类导航三项：`OEM成品` / `提取物` / `食品添加剂`。
  Excel 在 A5 的批注："点击此处，可以定位到相应的页面位置" → 导航为**页内锚点跳转**，不是独立页面。
- 页面顺次排列三个区块，每个区块字段不同：

| 区块 | 表头字段 |
|---|---|
| Durlevel OEM成品 | No. / 产品图片 / 产品英文名字 / 剂型 / 规格 / 产品标签 / 备注 |
| Durlevel 提取物 | No. / 产品图片 / 产品英文名字 / 含量 / 比例 / 备注 |
| Durlevel 食品添加剂 | No. / 产品图片 / 产品英文名字 / 剂型 / CAS号 / 备注 |

- 三类共有字段：图片、英文名、备注；差异字段：规格/标签（OEM）、含量/比例（提取物）、CAS号（食品添加剂）；剂型为 OEM 与 添加剂 共有。

### 3. 联系我们（Sheet「联系我们」）
- 顶部 Logo；下方 **7 组业务员名片**，每组字段：**照片 / 业务员（姓名）/ 电话 / WhatsApp / 邮箱**。
- 业务员数量应可在后台增减，不写死 7 个。

## 二、关键设计决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 前台语言 | **英文** | 外贸站，受众为海外客户；Excel 表头即为"产品英文名字" |
| 后台语言 | **中文** | 使用者是公司内部人员 |
| 分类实现 | 固定 3 类（代码内枚举），区块标题可在后台改 | Excel 中三类字段结构不同，属于结构差异而非数据差异 |
| 分类导航 | 同一页面内锚点 + 吸顶导航 | 遵循 Excel 批注 |
| 搜索 | 服务端 `?q=` 过滤（跨三个区块），无 JS 也可用 | 简单、可被收藏/分享 |
| 会话 | HMAC 签名 Cookie（无状态），无需 Redis | 单机部署即可，重启不掉线 |
| 数据库 | SQLite（单文件） | 产品/业务员/用户量级小，零运维，备份=复制一个文件 |
| 技术栈 | Node.js + Express 5 + EJS + SQLite | **无前端构建步骤**，`npm ci && npm start` 即跑，便于公司自行维护与迁移 |

## 三、站点地图与权限

```
/                      登录页（公开，整站唯一公开页）
POST /login            登录
POST /logout           退出

── 以下需登录 ───────────────────────────
/products              产品列表页（#oem / #extract / #additive 锚点 + ?q= 搜索）
/contact               联系我们（业务员名片）

── 以下需管理员 ─────────────────────────
/admin                 后台概览
/admin/products        产品管理（列表 / 新增 / 编辑 / 删除 / 排序 / 上下架 / 图片上传）
/admin/staff           业务员管理（同上 + 照片上传）
/admin/users           账号管理（新增用户、改密、停用、设角色）
/admin/logs            访问记录（账号 / IP / 时间，可筛选与导出 CSV）
/admin/settings        网站设置（Logo、站名、区块标题、页脚、联系页说明、日志时区与保留期）
```

权限矩阵：

| 角色 | 前台浏览 | 后台管理 |
|---|---|---|
| 未登录 | ✗ | ✗ |
| user | ✓ | ✗ |
| admin | ✓ | ✓ |

## 四、数据模型

```
users     id, username(唯一), password_hash, display_name, role(admin|user),
          is_active, created_at, last_login_at
products  id, category(oem|extract|additive), name_en, image_path,
          dosage_form(剂型), spec(规格), tags(产品标签),     -- OEM
          content(含量), ratio(比例),                        -- 提取物
          cas_no(CAS号),                                      -- 食品添加剂
          remark(备注), sort_order, is_active, created_at, updated_at
staff     id, name, title, photo_path, phone, whatsapp, email,
          sort_order, is_active
settings  key, value      -- logo_path / site_name / brand_name / 区块标题 / 页脚 /
                         -- log_timezone / log_retention_days 等
access_log id, occurred_at(UTC), user_id, username, role,
          event(login_success|login_failed|logout|page_view),
          path, ip, user_agent
```

`access_log.username` 是事件发生时拷贝进去的，账号被删除后历史记录仍可追溯。
时间统一按 UTC 存储，展示时再按配置时区换算，避免服务器迁移或夏令时导致记录错乱。

三类产品共用一张表 + `category` 判别列，差异字段留空：后台表单按分类只渲染该分类需要的字段，前台按分类渲染对应表头。这样新增字段/分类时无需迁移多张表。

## 五、安全措施

- 密码 **bcrypt** 哈希存储，不存明文；
- 会话 Cookie `HttpOnly` + `SameSite=Lax`（生产 `Secure`），HMAC-SHA256 签名防篡改；
- 所有写操作带 **CSRF Token**；
- 登录 **失败次数限流**（同 IP 连续失败后锁定一段时间），防爆破；
- **关闭自助注册**（无注册路由，符合 Excel 要求）；
- 上传文件白名单（jpg/png/webp/gif）+ 大小上限 + 随机重命名，杜绝上传脚本；
- 管理员不能停用/删除自己，且系统始终保留至少一个可用管理员；
- 访问记录保留登录成功/失败、退出、页面浏览，便于安全审计；IP 属个人数据，默认 180 天自动清理。

## 七、部署

1. 服务器安装 Node.js 20+；
2. `npm ci` → 复制 `.env.example` 为 `.env`，**改掉 `SESSION_SECRET` 和初始管理员密码**；
3. `npm run init-db` 建库并生成初始管理员；
4. `npm start`（建议用 `pm2` 或 `systemd` 守护）；
5. 前面挂 Nginx 做 HTTPS 反向代理，并设 `TRUST_PROXY=1`；
6. 备份：定期打包 `data/site.db` 与 `public/uploads/` 两项即可。
